### Shepherd

**You own one sweep, not the PRs. Each run clears what an agent can clear on every open PR the operator wrote, lands what is verified, and speaks only when something merged or needs the operator.** A scheduled task runs this playbook, locally or in the cloud. The task prompt is the operator's standing request. It names the GitHub owners to sweep, the merge grant (if any), each repo's approval bot and re-review command, and how to reach the operator.

Every run starts from GitHub's current state and keeps no state of its own, so a crashed or skipped run costs nothing and two runs in a row converge.

1. **List the queue fresh.** `gh search prs --author @me --state open --draft=false --owner <owner> --json repository,number,url,updatedAt` for each owner the task names. Drafts are the operator's work in progress, so leave them.
2. **Skip PRs someone is already on.** One writer per branch. Skip a PR whose head commit is under 30 minutes old, or whose branch has a running session (`mcp__ccd_session_mgmt__list_sessions` when the session has it). In a `gh stack`, work only the frontier per `playbooks/babysit.md` step 2.
3. **Classify each PR.** Run `scripts/merge-gate/merge-gate <pr> --repo <owner>/<repo>` without `--merge` (`--stack` on a stack's frontier). Sort its reasons with the buckets in `playbooks/opening-a-pr.md` step 4, checked in this order. Any "back to Babysit" reason gets an owner pass (step 4). Any transient reason waits for the next run. Decision `merge`, or `needs-human-approval` as the only reason when the task's grant covers it, lands (step 5). Anything left goes on the operator list (step 6). So does a PR whose latest approval-bot verdict asks for a human, however clean it is.
4. **One owner pass per PR with agent work.** Spawn a fresh background `pstack:poteto-agent` per PR, with `isolation: "worktree"`, on the code-delegate model from `references/models.md`. Brief it to run one pass of `playbooks/babysit.md` in `drive` mode without `/loop`: conflicts, then threads, then CI, one push wave, replies citing the commit, then return. When the PR has no unresolved thread and CI is green on its head, the owner runs the task's re-review command if a bot has not reviewed the head yet, and requests the approval bot once the bots are clean. The next run picks up whatever the pass left.
5. **Land under the grant.** Without a grant, put the PR on the operator list as merge-ready. With one, run `playbooks/shipping.md` steps 1 to 4 for it: an independent verifier, then `scripts/merge-gate/merge-gate <pr> --merge`, or the grant's own merge command when the grant covers the refusal. Read the PR back to confirm it merged.
6. **Notify on change only.** One message per run, sent through the session's push-notification tool, or else the channel the task names. It lists each PR this run merged, and the operator list with the one action each PR needs from the operator. Send the operator list only on the task's digest run (for example, the first run after 09:00 local), so an unchanged wait does not ping every hour. A run that merged nothing outside the digest run sends nothing.

**Reply:** one line per PR touched (action taken, or why skipped), the PRs merged, the operator list, and whether a notification went out.
